# fpga/ - gateware side of the FreeWili 2 FPGA BSP

```
constraints/fw2.pcf        iCE40UP5K-SG48 pin constraints (from the FreeWili 2 stock gateware, provenance header)
lib/spi_slave/             SPI mode-0 byte slave used by the register bus (from the stock gateware, provenance header)
lib/fw2_stream_fifo/       4 KB RX + 256 B TX stream FIFO in EBR (fw2_stream_fifo.v, fw2_fifo_sync.v)
shell/fw2_shell.v          the mandatory top (pads, arm gate, register bus, ID block, FIFO, user_core slot)
shell/fw2_pad.v            explicit SB_IO bidirectional pad (never a constant-folded driver); fw2_pad_od.v open-drain variant
shell/fw2_io_buffer.v      profile-driven direction logic
shell/fw2_spi_slave.v      register-bus slave with hold-address bursts and a read strobe (derived from the stock gateware)
shell/fw2_rst_ctrl_reg.v   reset register with a self-clearing request bit (derived from the stock gateware)
shell/fw2_profile.vh       mode codes, signal indices, FW2_PACK_PROFILE
shell/fw2_regs.vh          register map constants
shell/fw2_user_core.vh     the fixed user_core port list (contract rule 1)
shell/fw2_lint.vlt         verilator waivers (each explained)
sim/spi_bus_bfm.v          SPI mode-0 register-master model (reg_write/reg_read/burst_read/burst_write/io_config_en)
sim/tb_shell.v             shell testbench: ID block, directions, user window, FIFO, arm gate
sim/tb_design/             the test design the shell testbench runs against (user_core.v drives every output)
sim/check_netlist_pads.py  gate-level check: no inout pad of the synthesised netlist is tied to a constant
```

Design-specific constants come from `fw2_design_id.vh`, generated by
`tools/gen_design_id.py` from `designs/<name>/design.toml` into the build
directory. `docs/drivers/shell.md` explains the bus, the direction bits and
the arm gate; `docs/fpga-design-contract.md` the rules.

`fwfpga build` runs every step below for you. The raw commands are here so you
can see exactly what happens, or run a step by hand.

## Toolchain

oss-cad-suite `2026-10-31` (yosys 0.70+286, nextpnr-ice40 0.11.1-84, icepack,
iverilog 14.0 devel, verilator 5.053 devel). On Windows put both `bin` and
`lib` on `PATH` (nextpnr needs `libpython3.11.dll` from `lib`), run
`verilator_bin.exe` directly with `VERILATOR_ROOT=<suite>/share/verilator`
(the `verilator` perl wrapper lacks `Pod::Usage`), and note that the yosys
`` `include `` search is relative to the current directory and `-I` paths only.

## Build commands (run from the repo root)

```sh
SHELL_SRCS="fpga/shell/fw2_shell.v fpga/shell/fw2_pad.v fpga/shell/fw2_pad_od.v fpga/shell/fw2_io_buffer.v fpga/shell/fw2_spi_slave.v fpga/shell/fw2_rst_ctrl_reg.v fpga/lib/spi_slave/spi_slave.v fpga/lib/fw2_stream_fifo/fw2_stream_fifo.v fpga/lib/fw2_stream_fifo/fw2_fifo_sync.v"
D=hello_blink; B=build/designs/$D; mkdir -p $B
yosys -q -l $B/yosys.log -p "read_verilog -I fpga/shell -I designs/$D $SHELL_SRCS designs/$D/user_core.v; synth_ice40 -top fw2_shell -json $B/$D.json"
python fpga/sim/check_netlist_pads.py $B/$D.json      # every inout pad is a real SB_IO (see 'Pads' below)
nextpnr-ice40 --up5k --package sg48 --pcf fpga/constraints/fw2.pcf --json $B/$D.json --asc $B/$D.asc --freq 31.25 --report $B/report.json -l $B/nextpnr.log -q
icepack $B/$D.asc $B/$D.bin
```

(`-I designs/$D` is where `fw2_design_id.vh` is found; the CLI points it at the
build directory instead. `fwfpga build` then packs the `.bin` into a
`.fwfpga` container.)

Lint (must exit 0, warnings are fatal):

```sh
verilator_bin --lint-only -Wall -Ifpga/shell -Idesigns/$D --top-module fw2_shell fpga/shell/fw2_lint.vlt $SHELL_SRCS designs/$D/user_core.v
```

Simulation:

```sh
iverilog -g2012 -I fpga/shell -I fpga/sim/tb_design -o build/sim/tb_shell.vvp fpga/sim/tb_shell.v fpga/sim/spi_bus_bfm.v $SHELL_SRCS fpga/sim/tb_design/user_core.v && vvp -n build/sim/tb_shell.vvp
iverilog -g2012 -I fpga/shell -I designs/$D -o build/sim/tb_$D.vvp designs/$D/tb/tb_user_core.v designs/$D/user_core.v && vvp -n build/sim/tb_$D.vvp
```

`-Ptb_shell.SCK_HALF_NS=100` runs the shell testbench at 5 MHz SCK.

## Pads

Every bidirectional pad goes through `shell/fw2_pad.v`, an explicit `SB_IO`,
because yosys turns a plain `assign PAD = 1'bz;` into a pad that drives 0.
Read a pad through its SB_IO input (`rp_i[]`), never the port net.
`sim/check_netlist_pads.py` fails the build if any pad of the netlist is tied
to a constant.

## Adding a library module

New code: `fpga/lib/fw2_<name>/fw2_<name>.v` + `README.md` (what, ports,
registers owned, status), lint it through a design, test it in `tb_shell` or a
design `tb/`. Code copied from elsewhere keeps its provenance header.
